# town-shots

Quiet photo wall for Town / Voxelize captures. Deployed via GitHub Pages at [https://shaoruu.github.io/town-shots/](https://shaoruu.github.io/town-shots/)

## Design

The images are the site. Warm plaster ground, flush edge-to-edge masonry with 10px seams, zero radius, no shadows, one quiet sans.

- **Wall**: shortest-column masonry laid out from manifest `width`/`height`, so tiles reserve their exact footprint before the image arrives (no layout shift, no empty first paint). Tiles load the wall-sized WebP `thumb` (~100KB) and fade in over a plaster placeholder; the full-res original is only fetched in the lightbox
- **Tiles**: always-visible small capture time (Pacific) bottom-left on warm paper; the annotation unfolds beside it on hover. Neighbours dim softly. Video tiles have no badge — they show their `poster` frame and play silently on hover
- **Lightbox**: deep charcoal scrim, hairline close/chevrons, scroll-wheel zoom anchored to the cursor, drag to pan, pinch on touch, double-click to zoom. Esc / click outside / `←` `→`. Opens instantly from the cached thumb and sharpens into the original. Videos play inline, muted-first
- **Type**: system sans only, 10–11px uppercase with tracking for labels; ink `#1C1A17`, muted `#6E6860`, ground `#F0EDE6`

## Quality bar (sync job)

Fewer excellent tiles beat a junk pile. When syncing from the screenshots folder, apply these filters before writing to `public/manifest.json`:

- **Min resolution**: images ≥ 1280×720 (prefer ≥ 1920 on the long edge); videos ≥ 1080p
- **Skip** anything matching `*-before*`, `*-debug*`, `*clip-sheet*` / contact sheets, and tiny crops (< 800px on either edge)
- **Burst frames**: keep one representative frame per burst (same subject, timestamps within ~2s), not the whole sequence
- **Prefer** files from a `highlights/` folder when both a raw and a curated version exist
- **Composition sanity**: drop shots where the subject is indistinguishable at thumbnail size (empty terrain, far-off subjects, UI overlays). When in doubt, leave it out

The Sep 13 seed batch was pruned by hand under these rules (contact sheet, an unfocused wide, an empty flow-test plain, and a 720p still that duplicated the video's opening frame).

## Data Model

The gallery reads from a simple static structure:

```
public/
  media/          # Full-res originals: images (.png, .jpg, .webp) and videos (.mp4, .webm)
    example-1.png
    example-2.mp4
    derived/      # Generated by `npm run derive` — wall thumbs + video posters (WebP)
      example-1.webp
      example-2-poster.webp
  manifest.json   # Single JSON file listing all media items
```

### Manifest Schema

`public/manifest.json`:

```json
{
  "items": [
    {
      "id": "unique-id",
      "src": "media/example-1.png",
      "type": "image",
      "capturedAt": "2026-09-18T14:32:00.000Z",
      "thumb": "media/derived/unique-id.webp",
      "annotation": "Butterfly meadow in bloom",
      "tags": ["meadow", "butterflies", "nature"],
      "width": 1920,
      "height": 1080,
      "sourcePath": "/path/to/original.png"
    }
  ]
}
```

**Fields:**
- `id` (required): Unique identifier for the item
- `src` (required): Relative path from `public/` to the media file
- `type` (required): `"image"` or `"video"`
- `capturedAt` (required): ISO 8601 timestamp (displayed in Pacific time)
- `thumb` (optional, generated): Wall-sized WebP derivative shown in the grid; falls back to `src`
- `poster` (optional, generated): First-frame WebP for videos, shown on the tile and before playback
- `annotation` (optional): Short description
- `tags` (optional): Array of tag strings
- `width`, `height` (recommended): Dimensions in pixels — drives masonry placement and reserves tile space before load
- `sourcePath` (optional): Original file path for reference

## Syncing Media

To add new screenshots/videos:

1. **Copy media files** into `public/media/`
2. **Regenerate `manifest.json`** with entries for each file
3. **Run `npm run derive`** — writes WebP thumbs (≤1400px wide, q82) and video posters (frame at 0.5s) into `public/media/derived/` and fills in `thumb` / `poster` on each item. Idempotent; `--force` regenerates. Needs `ffmpeg` with libwebp
4. **Push to `main`** — GitHub Actions will rebuild and deploy

The manifest can be generated by any script that scans `public/media/` and extracts metadata (timestamps, dimensions, etc.). Export videos with `-movflags +faststart` so the `moov` atom leads and the browser can read metadata before the whole file arrives.

## Deployment

GitHub Pages is configured via Actions (`.github/workflows/deploy.yml`). Every push to `main` triggers a build and deployment. The site base path is `/town-shots/` (`vite.config.ts`); the manifest fetch and every media `src` resolve through `import.meta.env.BASE_URL`, so the same build works in local dev at `/` and on Pages.

To enable GitHub Pages:
1. Go to repository Settings → Pages
2. Set Source to "GitHub Actions"
3. The workflow will deploy on the next push
